# 精读契约（每次任务都必须遵守）

## 交付物

一次合格的精读必须产出并交付：

1. 合并 Markdown（`<文档名>.md`）：全文按阅读顺序排列，图表在其原始位置以图片引用出现，图题紧随其后。
2. 逐块 JSON（`pages/page_*/` 下的 `*_res.json`）：每个块含 `block_label` / `block_content` / `block_bbox` / `block_order`。
3. 切割图（`imgs/`）：每张图表一张完整图片，文件名含页码与坐标。
4. 一句诚实评估：图文配对情况、漏检情况、OCR 可疑点。

## OCR 判读纪律

OCR 文本是可能出错的中间产物，切割图才是事实来源。

- 图题、正文、公式出现乱码式错字（真实案例："Figure.utciooflym ricle.acamvlatitiedrom…"）时，不要照读。打开对应切割图核实后再陈述。
- 引用任何图表结论前，必须实际查看该图的切割图片。图中坐标轴、图例文字（旋转、小号）OCR 噪声大，一律以图为准。
- 某页存在 `figure_title` 块但没有对应切割图，说明该图（通常是线条示意图）被版面检测漏检。主动向用户指出，必要时渲染该页截图手动补切，不要假装读到了。
- 区分两类陈述：正文等高置信文本可直接转述；图题、图中数据、公式须标注"经原图核对"。

## 背景认知（解释纪律的由来）

- 本产线把整页渲染成位图再 OCR，不利用 PDF 内嵌文字层，因此小字号文本错误率上升。这是架构决定的，不是参数没调好。
- 几十页扫描件只出几行字、图表整段失踪，是 OCR 管线的已知故障模式。遇到输出与页数/篇幅明显不成比例时，先怀疑解析失败，而不是文档真的没内容。
- 统计图表（折线/柱状/散点）切割可靠；纯线条示意图可能漏检。
